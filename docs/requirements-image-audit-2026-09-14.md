## 2. 尚未完整落到文档的四处

以下是原图到需求的记录或规则缺口，不等同于已经批准、应该立即开发的功能。

### A. 角色发现与筛选

原图第 3 页 §3.3 明确出现 **Trending / 热门、Gender / 性别筛选、Safe / 安全筛选、Preset Library / 预设角色库、Create Custom Character / 自定义角色**。

客户需求 §8.4 已有角色性别字段、预设和自定义角色，后台文档也有预设管理；但未说明前三种发现/筛选能力采纳、暂缓还是移除。角色的性别输入字段不等于预设库按性别筛选。

建议补充处置记录：当前仍以已启用预设和自定义角色为准；若推进预设库筛选，需定义可筛字段。热门排序的数据来源、统计范围和周期，及“安全”的标注依据、责任人和适用范围，均需先确认，不能伪造热门或承诺未经定义的内容安全。

### B. 必选标签的必填口径

原图第 2 页 §2.4 标题是 **Required Tags & Metadata / 必选标签与元数据**，包括受众、基调、视频用途、市场、内容敏感度。

客户需求 §8.3.4 仅写“建议分为”这五组，未说明是否每组必须选、是否有默认值、未知时如何提交。目标受众另有必填规则，但不能据此推导其余四组也必填。

建议补充逐组“必填/选填/已移除”及最低数量、默认值的明确决定，并说明其与现有目标受众、视频目标字段是否重复。确认前保持现有校验，不恢复原图的笼统必填要求。

### C. 制作限制如何进入资料包

原图第 4 页 §4.6 将 **Constraints / 敏感或限制说明** 单列，内容包括敏感主题、品牌规范、法律限制和其他重要限制。

现有文档有“敏感或需要避免的内容”、必须做/不能做附件，以及历史品牌规范类别；但 §8.8.2 汇总清单没有单列限制说明，也没有定义法律限制、品牌规范如何映射、展示和交接。已有 [资料包导出](./operations-workbench.md) 描述了真实字段和附件打包，并未定义一个新的统一限制对象。

建议先明确使用现有备注和附件聚合，还是增加独立字段；再写清客户确认页、管理员详情和导出包的一致展示要求。不得把“用户勾选授权”与制作内容限制视为同一个概念。

### D. 临时项目名与正式项目名

原图第 2 页右栏及第 5 页 §5.1.1 明确说由项目经理正式命名。客户需求 §8.3.1 和生产批注中虽有提及，但缺少名称字段、可见范围、修改权限与历史保留规则。

当前 [图书录入](./book-intake.md) 规定临时项目名可选，空白时采用书名；产品基线禁止管理员直接改写客户提交快照。这两点不能自动推出“管理员覆盖客户原项目名”的权限。

建议将正式命名保留为待确认：若需要，应讨论独立内部展示名、客户可见性、导出采用哪个名称以及审计记录。当前不修改客户提交内容。

## 4. 已覆盖或明确暂缓的事项

- 角色字段、六种视觉风格、参考图片、八项声音偏好、多参考音色、六类参考素材、六项创意方向：详细需求已有对应条目，后续可选旁白和色彩基调变更也有明确记录。
- 初稿/修订稿、时间点评论、局部批准、母版、多尺寸社交短版、项目归档：生产批注已记录并列出待确认问题，不是文档遗忘。
- 文件授权需要勾选还是签署附件：已经列在待确认事项，不另算遗漏。
- 手机版拍照、已保存草稿到桌面继续：移动端和草稿规则已覆盖；[上传恢复](./file-uploads.md) 明确未完成文件刷新后需重新选择，原图未要求跨设备续传同一上传流。
- 图片与视频“实时生成”、自动分镜、自动配音、自动剪辑：当前范围明确排除；外部制作流程的出现不等于本平台要内置生成引擎。
- 邮件尚未启用，不能因原图的反馈信封图标而恢复邮件开发。
- 后台截图中的设备告警、收费、回访、JQL、通用表单设计器、工时和聊天均不能直接移植为业务需求。

## 5. 建议推进顺序

1. 统一主需求中的必填、步骤、角色和已有增强入口，使其与专题规则一致。
2. 给四处未细化项补充明确的采纳/暂缓决定；优先讨论制作限制交接，之后再考虑角色发现和正式命名。
3. 继续维持客户与管理员 `zh-CN` / `en-US` 一致。未来新增标签、筛选项、限制提示及名称说明均需提供双语文案、稳定 ID 和一致的数据权限；客户自由输入内容不自动翻译。

本轮只新增该核对记录和索引入口，未修改业务代码、已确认范围或运行数据。

# 客户前端体验审查与优化方案

日期：2026-09-05。范围：实际客户端 http://127.0.0.1:5173，非 5180 参考原型。只做观察与方案，不修改产品代码。

## 总体判断

现有品牌配色、卡片、风格示例图与固定底部操作栏已有统一基础。最优先的工作是让客户明确“目前处于什么状态、需要处理什么、下一步去哪”，其次是缩短表单和手机浏览负担。

## 本次查看的页面

| 步骤 | 页面 | 评价 |
|---|---|---|
| 1 | 项目列表 | 结构清楚，但操作文案没有区分继续填写与处理退回 |
| 2 | 上传图书 | 输入分组正常，上传入口在长表单后方，可选内容占据首屏 |
| 3 | 桌面视觉风格 | 示例图清楚、选中边框明确；部分标签名称不贴切 |
| 4 | 手机视觉风格（390×844） | 两列图片适配良好；进度只剩数字，横向选项发现成本较高 |
| 5 | 退回编辑与沟通 | 自动定位需处理单元可用，但浮窗遮挡内容，入口与状态不统一 |
| 6 | 重新提交审阅 | 内容完整，但沿用初次提交结构，存在不可编辑单元的修改入口 |

## 第一批：状态与操作一致性（优先）

### 1. 让项目列表直接告诉客户要做什么

观察（图1）：普通草稿与退回项目的操作都叫“需求采集”；退回状态叫“待客户确认”，概览没有单独的待处理入口。
方案：
- 普通草稿：继续填写；显示上次步骤，例如“视觉风格 · 4/6”。
- 退回项目：查看反馈 / 处理退回；显示需要处理的单元数量。
- 已提交项目：查看进展；有交付物后才显示下载入口。
- 增加“待我处理”筛选，草稿删除放到更多菜单，降低误触和视觉竞争。
- 不把已有全部消息数伪装成未读数；未读提示需要真正的已读记录。

### 2. 补齐退回模式的完整呈现

观察（图5、6）：只有视觉风格开放，右侧下一步仍写“参考素材与创意方向”；审阅页其他部分仍有“修改”，底部仍可“返回参考素材与创意方向”；摘要显示草稿。禁用步骤背景变淡后，连线穿过文字，视觉上像删除线。
方案：
- 列表、编辑摘要、审阅页统一显示“待修改或回复”。
- 进度条下增加简短条幅：“本轮请处理：视觉风格”。展示对应原因入口。
- 所有修改/返回/下一步入口共用同一份可编辑单元权限；不可修改单元只读展示。
- 退回审阅以“本轮要求、我的回复、本轮调整、重新提交”为主，其他资料默认折叠。
- 使用“重新提交需求”文案；客户可仅回复说明并再次提交，无须强制修改。
- 禁用步骤保留文字清晰度，连线只放在圆点之间。

## 第二批：减少表单与手机使用成本

### 3. 调整上传图书的填写顺序

观察（图2）：首屏是书名、作者、卖点、简介，封面上传位于 1.2，需向下寻找；摘要重复展示已输入的信息。当前项目没有显示 AI 识别入口，本轮没有验证其交互。
方案：
- 将封面上传/拍照放在书籍信息前或旁边；识别功能启用时就近放置入口。
- 首屏突出必要信息；“卖点、简介、更多资料”作为可选补充，提供明确可选标识或折叠区。
- 右侧显示“还需完成的必要项”，可选的全书/节选不要混成似乎必须完成的清单。
- 字段错误就近显示，提交前汇总缺项并可跳转；如保留保存状态，用小型明确状态区，而非大量灰色备注。
- 保持只填空白字段的识别原则，识别完成后标识本次填入的字段，供客户快速核对。

### 4. 手机进度与长选项

观察（图4）：顶部只有数字/勾选，无法直接知道第5步是什么；横向色彩标签带滚动条。
方案：
- 顶部显示“4/6 · 视觉风格”，附“查看全部步骤”入口。
- 当前步骤固定显示；展开后用文字步骤列表跳转，不增加左右滑动翻页。
- 少量选项自然换行；较多的语言/类型使用可搜索的选择面板，并把已选值保持可见。
- 手机右侧辅助内容改为简短摘要入口；退回沟通使用可展开的底部面板，避免覆盖整个编辑区。
- 验收覆盖窄屏、英文长文案、键盘弹出后的输入区与底部按钮。

### 5. 将退回浮窗整合到编辑布局

观察（图5）：桌面浮窗展开后覆盖右侧摘要及部分风格示例；一个单元同时出现文字链接和下拉框。
方案：
- 桌面将沟通面板放入右侧栏，支持收起；保留清楚的沟通入口。
- 单个单元直接显示名称，多个单元才提供切换器。
- 固定展示当前单元退回原因，聊天区负责追问与回复，避免重要要求被后续消息淹没。
- 统一下拉框、输入框、时间与头像样式；消息数量与真正未读状态分开。
- 管理端历史记录继续保留，客户侧不增加复杂的历史浏览。

## 第三批：字段语义与视觉细节

### 6. 让选项表达实际含义

观察（图3、5）：名为“视频风格”的选项实际是舒缓、从容、动感、快速；当前样本允许四项同时选择，制作方难以判断主次。
方案：
- 改名为“节奏偏好”并明确单选/多选规则；如允许多种节奏，给“主要节奏 + 补充说明”。
- 不自行收紧业务校验，先确认是否允许“前缓后快”等组合。
- 用统一的选中标记，避免只靠颜色表示选中。
- 审阅页收紧键值间距、增强标签可读性；必要项目在上，空白可选项折叠。
- 保留当前配色与切换动画，优先修复表达和导航；进一步动效只服务反馈和定位。

## 验收范围与限制

- 已检查当前登录账号的客户侧界面、正常步骤跳转、退回自动定位、沟通展开收起、审阅入口和390×844布局。
- 没有修改表单、上传文件、发送回复或提交项目。
- 未覆盖登录、真实手机相机、移动键盘、完整旁白试听流程、普通客户账号权限差异及全部英文页面。
- 小字号和淡色辅助文字存在可读性风险；本轮没有做完整对比度测量、键盘遍历或读屏测试，不代表已通过无障碍合规。
- 建议执行顺序：退回导航/状态一致性 → 列表待办 → 上传与手机表单 → 字段语义与视觉整理。全程同步中英文。

## 2026-09-05 实施记录

已在 C:/Aigc 完成本批客户前端优化：
- 列表区分继续填写、处理退回、查看进展；新增服务端待我处理筛选，支持原有搜索和分页；草稿删除收入更多操作。
- 统一退回状态、下一步/返回与审阅修改入口；无关审阅区默认折叠，重提使用明确文案；校验错误按实际所属单元定位。
- 桌面沟通使用独立侧栏，手机按需展开底部面板；单单元不显示重复下拉框，退回原因固定展示，保留双方头像与消息。
- 封面上传放在书籍信息前；可选资料、卖点和简介可折叠，AI识别成功显示本次填写字段；不改变只填写空白字段的规则。
- 手机展示当前步骤名并可展开文字步骤；底部操作保持可见；类型、语言支持搜索并保留当前选项；少量选项换行。
- 节奏字段更名为节奏偏好并明确可多选；新增文案同步中英文。

验证：客户前端全套145项通过，随后新增2个审阅校验用例及搜索测试，相关22项通过；后端115项通过；客户前端和后端构建通过。独立代码复核发现的退回校验入口问题已修复。
实际浏览器检查了桌面退回侧栏、手机步骤展开、英文手机上传页、选项搜索及待处理筛选。没有修改真实项目、发送回复或再次提交。实体手机相机、软键盘弹出状态不在本次验证范围。

后续可单独扩展：服务端记录上次停留步骤、列表返回单元数量、精确字段修改对比与真正未读数。本批没有用推测的步骤或消息总数代替这些数据。

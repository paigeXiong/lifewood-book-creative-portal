# 客户产品需求登记平台：当前交付范围

## 1. 产品定位

当前产品只解决一件事：客户登录后登记“书籍相关的产品制作需求”，保存草稿并正式提交给 Lifewood。

本阶段不是工单流转系统，也不是制作管理系统。制作执行、内部节点流转、成片审阅、返修、交付和 AI 能力均不在当前范围内。

## 2. 系统边界

平台由以下正式组成部分构成：

1. 客户登记前端：用于查看自己的登记记录、创建草稿、填写表单、上传资料和提交。
2. 平台正式 API：负责用户数据隔离、草稿、附件、配置项、校验、幂等提交和只读提交记录。
3. 平台数据库与文件存储：由平台自身管理，不依赖本地测试 API。

测试控制台只是开发工具，必须保持可移除；它使用平台同一套真实账户与会话，不得提供假身份或绕过登录。

## 3. 核心规则

- 用户只可以访问自己的登记记录。
- 草稿可以继续编辑；已提交记录对客户只读，不提供修改或删除入口。
- 书籍封面、原稿、品牌资料和参考资料必须使用真实上传文件，不生成伪封面或伪头像。
- 枚举、音色、文件分类、限制和可选项由服务端配置并按语言返回；前端不得硬编码业务枚举。
- 允许自定义值的字段必须明确建模为“预设选项 + 自定义输入”，不能把所有下拉框都做成封闭枚举。
- 所有用户可见文案和服务端选项都必须兼容 `zh-CN` 与 `en-US` 路由。
- 提交操作必须支持幂等键和版本冲突检查，避免重复提交或覆盖其他窗口中的修改。

## 4. 登录

- 平台自带正式账户与登录能力，不再依赖外部登录 API，也不提供本地假账号。
- 首次使用时由负责人创建首个账号；仓库、安装包和启动脚本不得携带默认账号或默认密码。
- 密码只以 ASP.NET Core `PasswordHasher<TUser>` 哈希存入 SQLite；浏览器只保存 HttpOnly 会话 Cookie，不保存密码或 Token。
- 登录接口按来源 IP 限流；同一账号连续失败 5 次后锁定 15 分钟。
- 所有修改类 API 都校验 CSRF Token，项目数据和上传文件按真实用户 ID 隔离。
- 页面在没有真实头像图片时不生成伪头像；只显示用户姓名和账号信息。
- 当前真实登录未来可通过认证适配层替换为企业 SSO，但不是本阶段的外部依赖。

## 5. 明确不做

- 内部制作流程与节点看板
- 任务派发、制作人员管理和进度推进
- 视频审阅、逐镜反馈、返修和交付
- AI 文案、图片、视频或音色生成
- 客户对已提交记录进行增删改

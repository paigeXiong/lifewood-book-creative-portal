# 运营工作台与项目资料导出

本轮新增能力尚未发布。后台新增 `/workbench`；运营登录后默认进入工作台，管理员和平台负责人仍可使用原有概览。界面支持简体中文和英文。

## 队列与范围

服务端提供进行中、待跟进、等待客户、24 小时内到期、已逾期、近 7 天交付、待分配七个队列。统计与列表使用相同的权限、搜索和“只看我负责”条件。队列可重叠，不应相加当作项目总数；已撤回交付不计入近期交付。最近交付队列可以包含已完成项目。

项目列表每页 20 条，支持回车搜索、URL 保留筛选状态、每分钟刷新和手动刷新。运营仅看到当前分配给自己的项目，待分配队列对运营为空；管理员和平台负责人可查看所有已提交或有退回历史的项目。普通未提交草稿不进入工作台。

## 内部跟进期限

项目详情中通过“设置跟进”打开编辑框，按浏览器本地时区输入，服务端以 UTC 保存。该字段独立于客户要求的截止日期。需要 `admin.projects.workflow` 权限；保存携带独立版本号，过期版本返回冲突，防止覆盖其他同事的修改。

后台每分钟检查一次：首次进入到期前 24 小时范围时生成一次提醒，首次逾期时再生成一次。停机错过预提醒窗口则恢复后直接生成逾期提醒，不补发过时的预提醒。独立持久记录按项目、期限版本、负责人和提醒阶段去重，重启或清理通知历史不会重复产生提醒。

提醒复用站内通知的接收规则和偏好：默认有效负责人，无负责人时回退给管理员/平台负责人。重新设定、清除期限、改派负责人、完成或关闭项目使旧提醒失效；改派后的新负责人可收到当前阶段提醒。完成本次跟进会清除期限；关闭项目不能设置新期限，但允许清除已有期限。角色降为客户后不可查看内部跟进提醒。

## 资料包

详情页“导出资料包”需要 `admin.projects.export`，固定角色 owner/admin/operator 拥有此权限，仍检查项目范围。

ZIP 包含：

- `brief.html`：离线可阅读的项目需求说明、双语字段标签与附件目录；配置选项名称采用已有提交快照。缺少快照（包括正在退回修改的项目）保留原始选项编号并明确说明。
- `project.json`：当前项目表单数据，便于交接或后续处理。
- `book/`、`characters/`、`style/`、`references/`：当前项目实际引用的上传附件。内部备注、审计、账号记录及未引用历史附件不包含在包中。

外部链接、预设图片和配音试听保留引用，不自动联网抓取。总上传附件上限 1 GB；超过上限可分别下载附件。缺失、待写入或大小不一致的附件会阻止导出并显示错误，避免无提示地产生不完整包。

后端用临时文件流生成 ZIP，检查剩余存储空间；生成后复查账号会话、权限、项目归属和版本，再记录导出审计并发送。请求取消或下载完成后清理临时文件，异常停机后的残留在启动时清理。前端提供打包状态和取消按钮；详情卸载或账号切换后丢弃未完成的下载。下载到个人设备的文件不受平台后续权限变更控制。

## 接口

- `GET /admin/workbench?queue=&search=&mine=&page=&pageSize=`
- `GET /admin/projects/{id}/followup`
- `PUT /admin/projects/{id}/followup`：`dueAt`（ISO 时间或 null）、`expectedVersion`
- `POST /admin/projects/{id}/export`：ZIP 响应，保留 CSRF 与账号绑定校验

写入与导出均记录项目级操作审计。

# 持续读写与资源监测

`npm run bench:sustained` 将混合验证扩展为有节奏的持续负载，观察真实限流配置下的保存、上传重放、读取及进程资源情况。它用于稳定性回归，不测系统最大吞吐量。

## 运行

当前资源采样支持 Windows；需要 Node.js 22.13+、PowerShell 和 .NET 10。使用独立构建目录，不占用正在运行的开发服务文件：

```powershell
dotnet build services/platform-api/Lifewood.PlatformApi.csproj -c Release --artifacts-path C:/Aigc/artifacts/sustained-dotnet
npm run bench:sustained -- artifacts/sustained-dotnet/bin/Lifewood.PlatformApi/release/Lifewood.BookPortal.Server.dll
```

默认 180 秒。可传 `--seconds=10` 执行冒烟，允许 10–1800 秒；该参数只适用于持续模式。所有数据和日志位于独立的 `artifacts/api-benchmark/<UUID>`，固定测试端口 5097，不接受现有平台 URL 或业务数据目录。完整隔离规则见 [混合读写验证](./mixed-load-validation.md)。

可选 `--idle-seconds=120` 在所有读写工作结束后、故障检查与重启前，对同一后端进程增加无请求观察，默认关闭。该参数仅用于持续模式；允许 0（关闭）或 10–600 秒。不会触发 GC、清缓存或重启来制造内存回落。

启用空闲观察时，`resources.summary` 覆盖负载与空闲合计，不能直接作为纯负载均值。`report.idle` 记录实际起止时间及资源样本的起始索引、结束索引（不含结束索引）。分析时分别切片，舍弃相位边界邻近样本；空闲 CPU 只用空闲切片内部的累计 CPU 差值。请求延迟和 `mixed.durationMs` 仍仅覆盖负载阶段，不把等待空闲混入请求延迟。

## 工作负载

背景为 10,000 条较重的合成 JSON 项目，限制与真实性说明沿用混合验证文档。两个客户各创建两个通过真实校验的项目，读取中英文选项并保存双语内容。

每个项目先连续保存八次、首次上传约 1 MiB PNG 并验证重放；随后反复保存，在持续保存第 1、11、21……次重放同一图片上传；本次保存和可选重放完成后等待最多六秒，最后一轮等待按剩余时长截断。四个读线程分别读取两位客户的列表、客户统计、管理员列表，完成响应后等待 100 ms，再继续读取，直到写流程结束且至少各完成 100 次请求。最后执行真实校验、提交及提交重放。

平台默认每账号每分钟最多 60 次写请求。冒烟阶段曾因请求过密得到 429，脚本据此调整节奏，未修改或绕过平台限流。报告记录初始保存次数和各项目实际完成次数；任何非预期 429 都会让测试失败，不静默重试。

持续期间主要写入是草稿保存和已有图片上传重放。首次文件落盘与提交仍各只有四次，不代表持续创建新项目、大文件写入或大量提交压力。

## 验收内容

- 读取响应总数、分页、分类和客户数据隔离符合预期。
- 保存版本递增；最终提交保留每个项目最后一次保存内容。
- 重复上传不增加附件或版本，重复提交不重复递增版本。
- 额外同版本保存竞争恰好一个成功、一个 409；重新加载后重试成功。
- 旧版本上传返回 409，另一客户读取和上传返回 404。
- 写完后检查数据库完整性与提交快照；停止再启动隔离服务，比较完整项目数据与文件 SHA-256，磁盘恰好保留四个上传文件。

故障检查与重启发生在持续负载结束后；没有注入写入中途崩溃或真实断网。

## 资源与延迟口径

采样器只观察本轮新启动的后端 PID，通过进程启动时间防止 PID 复用，每秒获取累计 CPU 时间、工作集、私有内存、句柄和线程数。采样器以隐藏窗口运行，区间从 mixed 前首次样本到负载完成后停止采样前末次样本，包含初始八次突发保存、上传及末尾校验提交，排除项目准备、故障检查与重启。实际采样区间与配置时长、mixed 耗时分别记录。异常退出、无有效样本、计数不合法都会使本轮失败。

CPU 由相邻样本累计 CPU 时间差除以实际采样间隔计算：`100%` 表示用满一个逻辑核，可能超过 100%；另给出除以逻辑核数量后的整机比例。工作集包含共享及驻留页，私有内存也不等于 .NET 托管堆；未采集 GC、磁盘 I/O 或其他进程开销。资源报告不包含压测 Node 客户端与 PowerShell 采样器自身。

业务延迟包含完整 HTTP 响应，不含获取 CSRF、编解码断言、等待间隔。每 30 秒按请求开始时间分组，另保留与写请求重叠的读取子集；客户端 HTTP 重叠不等于数据库锁竞争。原始逐请求和逐秒数据均保留。

三分钟是有限时长稳定性观察，不能证明无内存泄漏、长期容量或生产网络体验。首次 JIT、缓存与内存提交都会影响短时间资源曲线。

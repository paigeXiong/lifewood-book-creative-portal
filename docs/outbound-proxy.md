# 出站代理

所有者在“系统配置 → 运行与网络 → 出站代理”设置全局连接方式，并可为每个 AI 接入、每个 OIDC 提供商单独覆盖。支持直接连接、跟随系统、自定义 HTTP/HTTPS 代理；服务覆盖还支持继承全局。SMTP 仍为直接连接，浏览器网络不受影响。

首次升级保留 AI 的系统代理行为，并将已有 OIDC 提供商设为直连。之后新接入默认继承全局。保存后用于新请求；已开始的请求保持原设置。系统模式沿用 .NET 的系统/环境代理和绕过规则，修改系统代理后应重启服务。

自定义代理填写 `http://主机:端口` 或 `https://主机:端口`，不附带路径、查询参数或用户名密码。认证为可选 Basic；用户名与密码需同时填写或同时清空。密码经 Data Protection 加密保存于数据目录的 `outbound-proxy.json`，接口和审计不返回密码。改变代理地址或用户名时，必须重新输入密码或清除认证。切换到非自定义模式会删除该范围的代理凭据。

代理连接失败不会自动改走直连。OIDC 保留 HTTPS、证书校验和公网目标限制，目标由服务器本地解析后，向 HTTP/HTTPS 代理发送指定公网 IP 的 CONNECT 请求；目标 TLS 仍验证原域名。因此服务器需要能够解析 OIDC 域名，代理需要支持 CONNECT 到该公网 IP。OIDC 的系统代理也只支持 HTTP/HTTPS 代理。

每个已保存接入可以“检查连接”：向已有 HTTPS 服务目标发送不带业务密钥的 HEAD 请求，不调用模型、不发送邮件。目标返回 401、403、405 等状态仍表示网络已连接，不代表业务认证成功。业务认证继续使用原有 OIDC 配置检查或实际 AI 调用。全局没有任意目标探测入口。

配置采用版本冲突检查；发生冲突时关闭编辑框并重新打开。代理配置和 Data Protection 密钥由现有整库备份一同保存，恢复备份后随服务启动加载。正式上线前仍需用部署环境的实际代理完成 AI 与 OIDC 端到端验收。

# Windows 安装与升级验证

本轮补充 Windows 安装器的真实服务演练，并修复备份目录的服务权限准备。代码尚未发布；实际 Windows 服务安装演练须在临时 CI 机器运行。

## 修复内容

运行时默认把备份放在数据目录的同级 `<数据目录>.backups`。原安装器只授予数据目录和恢复协调目录权限，没有创建这个备份目录；使用独立虚拟服务账号时，服务可能无法创建目录，进而启动失败。

安装器现在先校验数据与备份路径，再以提升权限的独立安装动作准备备份目录，之后执行其他目录创建。新目录只授予平台服务账号、SYSTEM 和本机 Administrators 完全控制，所有者为 Administrators。应用程序仍按原路径读取备份，不移动、不重建已有归档。

- 备份准备由已锁定的数据路径推导，升级时不能通过另传目录把数据切走。
- 拒绝网络路径、系统路径、链接、目录联接及无关非空目录。
- 已有备份树必须保留平台专用的所有者与权限；包含外部账号、拒绝规则或缺少服务权限时中止，不替用户重写整棵目录的权限。手工迁移、便携版创建或曾手工修改权限的备份，可能需要管理员先检查归属。
- 设置权限时逐级持有目录句柄，禁止目录被重命名或替换；创建新目录时直接使用私有权限描述符。
- 卸载不运行备份准备动作，数据库、备份及原数据路径记录保留。
- 安装失败提示同时适配中文和英文。

## 安装包构建隔离

CI 首次演练发现 WiX 默认会把输出 MSI 硬链接到中间文件。连续构建到不同输出目录时，旧目录的安装包也会随新构建被改写，导致测试版本失去独立性。现已禁用输出硬链接和符号链接，并让每次构建使用独立中间目录。CI 会在第二轮构建后重新计算第一轮中英文包的 SHA-256，确认其内容没有变化。已受影响的本机历史构建缓存不能按目录名推断版本，应重新构建并核对包内版本及校验值。

## 自动演练

`.github/workflows/installer-lifecycle.yml` 在临时 GitHub 托管 Windows 机器上运行。脚本要求 CI 标记、显式允许变量和提升权限，并拒绝已有平台服务、安装目录或生产数据记录的机器。

流程：

1. 使用同一份代码构建两个不同版本号的测试 MSI，中文包安装、英文包升级。这些安装包不会发布，也不会修改仓库版本号。
2. 启动真实 Windows 服务，确认使用平台虚拟服务账号。
3. 通过真实 API 创建负责人、客户、组织、已提交项目、图片和文稿、最终成品、带截图的反馈与通知回复，以及手动备份。
4. 暂时移除测试安装的原数据路径记录，确认升级拒绝执行，恢复记录后原服务和数据仍可使用。
5. 执行跨语言升级，故意传入另一个数据目录，确认仍使用原目录。
6. 卸载并重新安装，重新登录并核对项目字段、附件和成品字节、反馈通知与备份字节。

只上传无敏感内容的 `result.json`。测试密码、数据库、归档和 MSI 详细日志留在临时机器上，不作为 CI 工件上传。测试不发送邮件、不操作本地 5077/5173/5174 服务。

## 本机验证与边界

`node scripts/test-installer-fixture.mjs` 在独立的 5098 端口启动已构建服务，通过真实 API 核对业务数据，并检查进程重启后内容保留。重复初始化已有服务必须被拒绝。该检查还核对中英文接口文案和两端打包页面入口，不能代替完整浏览器视觉验收。

`test-installer-backup-path.ps1` 在提升权限时检查实际服务 SID、目录权限、原文件保留、外部显式权限、受保护子目录和链接拒绝；非提升权限时只验证无法擅自授予服务权限且不遗留备份目录，并明确报告未执行完整权限用例。

本轮已在本机通过业务数据重启保留、原有目录安全规则、非提升权限拒绝、运维脚本回归、MSI 会话与包内动作排序检查；中英文测试 MSI（测试版本 0.3.14）均构建成功，未安装或发布。当前用户没有提升权限，完整服务安装及专用权限创建仍以 CI 实际结果为准。

这套演练验证 MSI 生命周期与安装前拒绝条件。它使用同一代码的两个测试版本，**不代表跨历史版本数据库迁移已验证，也不代表安装事务中途失败的回滚已验证**。Linux systemd 实机安装、旧发布包升级和安装中途故障回滚仍是后续验收项；既有 `test-version-upgrade.mjs` 提供的独立进程升级检查继续保留。

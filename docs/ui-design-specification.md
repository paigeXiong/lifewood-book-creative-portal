## 1. 设计目标

本规范用于指导面向客户的书籍视频项目提交前端。主要使用者是向制作团队提交项目资料的客户。产品不是工单管理后台，而是具有品牌表达和服务引导能力的项目资料提交入口：在保证填写效率的同时，让客户理解需要提供什么、这些资料如何被使用，以及提交后会发生什么。

- 清楚知道当前填写到哪一步。
- 快速识别必填项、缺失项和保存状态。
- 在桌面端和手机端顺利上传书籍及参考素材。
- 在大量配置项中保持信息清晰、操作紧凑。
- 通过封面、风格示例、角色参考、参考音色和阶段说明呈现服务品质。
- 在关键步骤说明“当前选择会如何被制作团队使用”和“提交后会发生什么”。
- 使用 Lifewood 公司配色建立一致性，但不要求在页面中显式展示 Logo。
- 中文与英文界面具有一致的层级、密度和可读性。

## 3. 视觉方向

### 3.1 核心概念

设计方向定义为“品牌化项目资料提交体验”，视觉概念为“编辑台上的生长路径”：中性冷白灰承载高频操作，纸张米白只对应书籍与稿件，深绿对应 Lifewood 的可靠制作体系，藏红花橙对应从文字到影像的创作触发点。

界面保持安静、专业、紧凑，但不能退化为通用管理后台。品牌感和产品化体验主要来自：

- 冷白灰工作区与纯白内容面。
- 深绿导航和主要操作。
- 克制使用品牌橙色的当前步骤标记。
- 接近纸张编排的细分隔线和内容层级。
- 有业务意义的真实书籍封面、角色、风格缩略图和音频波形。
- API 未返回真实封面图片时不生成文字封面、首字母图片或其他伪图片占位。
- 只在关键流程节点出现的阶段解释、选择结果和后续动作说明。

不使用大面积渐变、玻璃拟态、装饰性发光、大量漂浮卡片或无业务意义的叶片背景。

### 3.2 标志性元素

唯一重点视觉符号可以借鉴品牌图形中的橙色六边形端点，但只作为小型状态标记，不显式展示完整 Logo。

使用场景：

- 当前向导步骤标记。
- 完成上传或提交后的关键成功节点。
- 选中视觉风格卡片的角标。
- 必要的品牌级提示图标背景。

限制：

- 一个视口内不重复大量使用。
- 不替代所有普通图标。
- 不用于错误、危险或删除操作。
- 不改变 Logo 本体或将其作为独立新 Logo 使用。

### 3.3 AI 表达边界

本期 UI 不呈现任何 AI 运行或生成能力：

- 不显示 AI 分析进度、生成进度或模型状态。
- 不使用“智能推荐”“自动生成”“AI 预览”等按钮和文案。
- 不以机器人、魔法棒、闪光等图标暗示系统会自动完成内容工作。
- 角色图片只表示客户上传的参考素材。
- 视觉风格图片只表示后台配置的示例素材。
- 参考音色只表示后台配置的试听素材。
- 项目资料包提交后的状态是“已提交/已接收”等确定性受理状态，不是 AI 生产状态。

页面可以出现业务名称“AIGC 视频制作”，但必须清楚表达这是工单要提交到的外部制作业务，而不是当前系统提供的功能。

## 4.3 色彩使用规则

- 页面默认背景使用 `surface.canvas`，不铺设大面积米黄色。
- 表单和内容面使用 `brand.white`。
- 顶部导航可以使用白色背景，底部以浅分隔线区分；不默认使用整条深绿导航，避免压迫复杂表单。
- 主要操作使用 `brand.castleton` 背景和白色文字。
- `brand.saffron` 只用于强调面，不用于白底上的小字号正文或主要按钮文字。
- 橙色背景上的文字使用 `brand.darkSerpent`。
- 错误状态必须使用错误图标或文字，不能只改变边框颜色。
- 成功状态使用绿色图标和明确文字。
- 聚焦状态采用深绿内描边，并可加一层浅橙外环；不能只使用低对比度橙色边框。

## 5. 字体系统

### 5.1 推荐字体

- 英文及数字：`Manrope`。
- 中文：`Noto Sans SC`。
- 系统回退：`Segoe UI`、`PingFang SC`、`Microsoft YaHei`、sans-serif。

```css
font-family:
  "Manrope",
  "Noto Sans SC",
  "Segoe UI",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

字体文件应在项目中合法自托管，正式界面不得依赖无法保证可访问的公共字体 CDN。

### 5.2 字号层级

| 角色 | 桌面端 | 移动端 | 字重 | 行高 |
| --- | ---: | ---: | ---: | ---: |
| 页面上下文标题 | 18px | 18px | 700 | 1.3 |
| 区块标题 | 18px | 17px | 700 | 1.35 |
| 卡片标题 | 15px | 15px | 650 | 1.4 |
| 正文 | 14px | 14px | 400 | 1.55 |
| 表单标签 | 13px | 13px | 600 | 1.4 |
| 辅助文字 | 12px | 12px | 400 | 1.5 |
| 数据编号 | 12px | 12px | 650 | 1.3 |

禁止使用占据首屏的大型营销 Hero。创建流程允许使用紧凑的页面标题和一句服务导向说明，但必须直接帮助用户理解当前步骤，不能成为装饰性宣传内容。

### 5.3 中英文排版

- 中文标题不使用额外字母间距。
- 英文大写短标签可以使用最多 `0.04em` 字距。
- 中英文混排使用统一基线，不用斜杠把两种语言同时塞进每个标签。
- 界面一次只展示当前语言；语言切换后整体替换文案。
- 项目编号、时长和文件大小使用等宽数字特性。

## 6. 尺寸与间距

### 6.1 基础间距

采用 4px 基准：

```text
4   微小间隔
8   图标与文字、紧凑控件
12  控件组内间隔
16  卡片内边距、字段间隔
20  中型区块间隔
24  页面主要区块间隔
32  大区块分隔，仅在桌面端使用
```

页面以信息密度优先，不使用 32px 以上的装饰性留白。常用页面间距控制在 8px、12px、16px 和 20px。

### 6.2 圆角

| 令牌 | 数值 | 使用场景 |
| --- | ---: | --- |
| `radius.control` | 6px | 输入框、按钮 |
| `radius.card` | 10px | 表单区块和选项卡片 |
| `radius.dialog` | 14px | 弹窗和抽屉 |
| `radius.pill` | 999px | 仅状态和短标签 |

禁止所有容器都使用胶囊形状。

### 6.3 阴影

- 默认卡片主要通过背景差异和细分隔线建立层级。
- 普通表单区块不使用明显投影。
- 弹窗、浮层和粘性操作栏可以使用柔和阴影。
- 不使用彩色大面积发光。

### 6.4 Lifewood 官网卡片参考

参考来源：[Lifewood 官网](https://lifewood.com/)，检查日期为 2026-08-21。

官网当前卡片可借鉴的视觉特征：

- 白色或浅纸色卡片表面。
- 约 16px 的圆角轮廓。
- 低透明度深绿细边框。
- 非常克制的深绿柔和阴影。
- 编号、类别、标题、说明和动作之间具有明确层级。
- 整张卡片在只有一个主要动作时可以点击。
- Hover 主要通过边界、阴影和细小位移表达，不依赖强烈颜色变化。

针对管理员工单工具的适配：

- 官网 36px 至 40px 的卡片内边距缩减为 12px 至 16px。
- 官网大型营销卡片的 16px 圆角只保留给选择卡片、媒体卡片和重要摘要；普通表单区块使用 8px 至 10px。
- 不使用官网的 128px 装饰编号。编号只在四步向导、真实顺序或确有识别价值时出现。
- 不复制官网的大篇幅说明和大面积空白；可以保留与当前任务直接相关的价值说明和明确流程 CTA。
- 不使用半透明玻璃卡作为普通表单容器。
- 不把所有字段分别放进卡片，避免卡片嵌套和视觉噪音。

建议卡片令牌：

```css
:root {
  --card-bg: #ffffff;
  --card-bg-muted: #f9f7f7;
  --card-bg-paper: #f5eedb;
  --card-border: rgb(19 48 32 / 15%);
  --card-radius-form: 10px;
  --card-radius-selectable: 16px;
  --card-shadow-hover:
    0 1px 2px rgb(19 48 32 / 5%),
    0 10px 28px -16px rgb(19 48 32 / 18%);
}
```

卡片类型：

| 类型 | 表面 | 圆角 | 内边距 | 阴影 | 用途 |
| --- | --- | ---: | ---: | --- | --- |
| 表单区块 | White/Sea Salt | 10px | 12–16px | 无 | 相关字段分组 |
| 可选卡片 | White | 16px | 12–16px | Hover 时轻微 | 视觉风格、参考音色 |
| 文件卡片 | White | 10px | 8–12px | 无 | 已上传文件 |
| 摘要卡片 | Paper/White | 10px | 12–16px | 无 | 确认页摘要、缺失项 |
| 媒体卡片 | White | 16px | 图片区 0、内容区 12px | Hover 时轻微 | 风格图片、音频试听 |

卡片交互规则：

- 整张卡只有一个动作时可以整体点击，并提供清晰的 Hover、Focus 和选中状态。
- 卡片内有播放、删除、更多等多个动作时，不将整张卡设置为一个模糊的大按钮。
- 选中状态使用深绿边框和橙色小标记，不只依赖阴影。
- 键盘 Focus 与 Hover 具有同等可识别性。
- 同一列表内的卡片标题和关键元数据对齐。
- 描述最多显示必要行数，完整内容通过详情或展开查看。

## 7. 页面骨架

### 7.0 上下文聚焦原则

每个页面必须先确定一个单一主要任务，并只保留完成该任务所需的上下文。上下文可以由以下一种方式承载：

- 简短页面标题。
- 一句必要的页面描述。
- 首次使用时出现的页面介绍。

规则：

- 标题、描述和介绍不默认同时出现。
- 用户已经从步骤条、返回入口或当前选中项理解页面时，不再重复显示页面标题。
- 页面介绍仅用于首次进入、解释复杂规则，或说明当前选择如何影响制作结果；应简短、可关闭或随步骤切换，不跨页面常驻。
- 项目填写页只显示当前步骤名称、保存状态和当前步骤需要的操作。
- “我的书籍视频项目”只显示筛选、搜索和创建项目操作，不显示后台批量管理功能；品牌化表达集中在封面缩略图、状态与细节品质。
- 角色编辑时聚焦当前角色，不常驻展示无关角色的完整资料。
- 上传页面只显示当前文件类别的限制，不重复展示整个项目资料包摘要。
- 与当前步骤直接相关的项目摘要、已选结果、素材预览和“下一步会发生什么”可以使用窄侧栏；无关上下文不得常驻占用视口。

页面上下文矩阵：

| 页面 | 必须聚焦的上下文 | 不常驻展示的内容 |
| --- | --- | --- |
| 我的书籍视频项目 | 筛选条件、结果数量、创建书籍视频项目 | 批量管理、分派、改状态、产品宣传 |
| 第一步：资料 | 当前步骤、客户与书籍资料、保存状态、紧凑项目摘要 | 角色、音色、完整工单详情 |
| 第二步：角色与风格 | 当前角色、角色列表、视觉选择、已选内容预览 | 上传清单、配音设置、通用产品介绍 |
| 第三步：配音与参考 | 参考音色、参考文件、创意要求、交接资料说明 | 角色完整字段、书籍资料详情 |
| 第四步：确认提交 | 完整项目资料包摘要、缺失项、提交动作 | 重复的流程介绍和营销内容 |
| 项目提交记录 | 项目编号、提交时间、受理状态、提交快照 | 编辑、删除、撤回、复制、生产管理操作 |
| 测试控制台 | 测试工单、状态和调试操作 | 正式产品介绍和品牌展示 |

布局要求：

- 最大内容宽度建议 1360px。
- 页面左右安全边距 16px 至 24px。
- 使用紧凑的两列或三列表单网格利用横向空间。
- 普通字段不因容器变宽而无限拉伸。
- 不设置跨步骤不变的完整摘要侧栏；宽屏可以显示随当前步骤变化的窄上下文侧栏，例如项目封面、已选风格、试听摘要或交接说明。
- 页面动作栏可固定在视口底部，但不得遮挡表单内容。
- 避免整个页面出现多层嵌套滚动；只有必要的长列表面板使用内部滚动。

## 7.2 平板端

- 双列表单保留到字段最小宽度不足为止。
- 必要摘要通过按需展开的抽屉显示，不常驻占用宽度。

## 8. 响应式断点

建议断点：

| 名称 | 范围 | 布局 |
| --- | --- | --- |
| `mobile` | `< 768px` | 单列、底部固定操作 |
| `tablet` | `768px–1099px` | 紧凑双列或单列，无常驻侧栏 |
| `desktop` | `1100px–1439px` | 两列或三列表单网格 |

断点以内容是否溢出为最终判断，不为特定设备型号单独设计。

## 9. 顶部工具栏

- 高度 48px。
- 白色背景，底部一条 `border.subtle` 分隔线。
- 主应用不显式展示 Logo，不为品牌占用固定导航空间。
- 左侧显示必要的返回入口、当前模块或当前工单编号，不重复页面介绍。
- 当前模块使用深绿文字和 2px 下划线，不使用大面积胶囊背景。
- 语言切换显示当前语言，例如“中文”或“EN”。
- 用户菜单显示头像、名称或组织，不单独显示无意义的欢迎语。
- 测试环境在导航中显示清晰的“测试环境”标识；正式构建不存在该标识和逻辑。

### 9.1 用户头像与用户菜单

- 桌面端在工具栏右侧显示 28px 至 32px 头像和用户昵称。
- 紧凑宽度下可以只显示头像，但按钮必须具有包含昵称的可访问名称。
- 用户昵称单行显示，建议最大宽度 120px，超出时省略并在用户菜单中显示全名。
- 所属组织、邮箱、角色等次要信息只在用户菜单展开后显示，不在工具栏常驻。
- 有头像时使用圆形或 8px 圆角方形裁切，整个产品保持一致。
- 无真实头像时，使用后端生成的首字母头像图片；背景使用稳定的中性色或浅品牌色，文字使用高对比度颜色。
- 前端必须用 `<img>` 加载头像图片 URL，不得使用文字标签和 CSS 背景拼装视觉头像。
- 生成图片优先取昵称中一至两个可识别字符；英文多词名称取首尾单词首字母，中文取一至两个字符。
- 头像旁存在昵称时，头像可以作为装饰图处理；只显示头像时必须提供用户身份的可访问名称。
- 用户菜单至少包含完整昵称、可选组织信息、语言切换和退出登录。
- 首期不提供编辑昵称、编辑头像或账户设置入口，避免暗示本系统可以修改外部登录资料。
- 头像加载不得导致工具栏高度或布局发生跳动。

需要覆盖的测试状态：

- 中文短昵称。
- 英文昵称。
- 超长昵称。
- 有头像。
- 无头像。
- 头像加载失败。
- 没有昵称但有用户名或邮箱。

## 11. 表单设计

### 11.1 表单区块

- 每个业务区块使用白色内容面。
- 区块标题、必要说明和操作放在同一行。
- 卡片内边距桌面 12px 至 16px，移动端 12px。
- 字段采用 8px 至 12px 的紧凑间隔。
- 宽屏下相关短字段并排；只有确实需要大段文字的字段和上传区独占整行。
- 不为每个字段套独立卡片。

### 11.2 标签和必填

- 标签位于控件上方。
- 必填使用文本或星号，并在表单顶部解释一次。
- 字符计数器位于输入区右下或标签行右侧。
- 帮助说明只解释输入方式，不重复标签。
- 错误提示紧邻字段，并说明如何修正。

### 11.3 输入控件

- 桌面端默认高度 40px，移动端至少 44px。
- 输入控件宽度必须与预期内容长度匹配，不默认设置为 `width: 100%`。
- 极短字段，例如数量、时长和短代码，建议最大宽度 120px 至 180px。
- 日期、电话和普通下拉框建议最大宽度 200px 至 280px。
- 姓名、邮箱、项目名称和普通文本建议最大宽度 320px 至 480px。
- 中等说明字段建议最大宽度 560px 至 720px。
- 只有内容简介、角色描述、创意方向等大段文字字段可以使用所在表单行的完整可用宽度。
- 移动端为了可用性，控件可以占满当前单列宽度。
- 边框使用 `border.subtle`。
- Hover 使用 `border.strong`。
- Focus 使用 2px 深绿描边及必要的浅橙外环。
- 禁用状态保持可读，不能仅降低整体透明度。
- 只读状态使用 `brand.seaSalt` 背景并显示只读含义。

### 11.4 下拉与动态选项

- 所有业务枚举由 API 返回，不在前端硬编码。
- 支持加载、无结果和加载失败状态。
- 数据量较大时使用服务端搜索和分页。
- 已停用选项在历史数据中仍能只读显示，但不能重新选择。
- 保存稳定 ID，显示当前语言文案。

### 11.5 长文本

- 普通备注默认 2 至 3 行，最大宽度建议 560px。
- 内容简介、角色性格、外貌、场景要求等大段文字默认 4 至 6 行，最大宽度建议 760px。
- 只有确认需要长篇输入时才允许使用完整内容宽度。
- 不因字段所在容器很宽就把编辑框拉到整个视口。
- 支持按需扩展高度。
- 明确显示字符数和上限。
- 自动保存时不抢夺焦点或改变光标位置。

## 12. 按钮

### 12.1 层级

| 类型 | 外观 | 使用场景 |
| --- | --- | --- |
| Primary | 深绿底、白字 | 继续、提交给制作团队 |
| Secondary | 白底、深绿描边 | 保存草稿、返回 |
| Tertiary | 无底色、深绿文字 | 编辑、查看详情 |
| Destructive | 白底、红字或红底 | 删除草稿、清空数据 |

规则：

- 一个操作区域最多一个主要按钮。
- 按钮使用明确动作：“保存草稿”“继续到角色设置”“提交给制作团队”。
- 不使用含义模糊的“确定”“提交”作为所有动作的通用文案。
- 加载状态保持原宽度，避免布局跳动。
- 仅图标按钮必须提供可访问名称和提示。

## 13. 文件上传组件

### 13.1 空状态

- 显示文件类别、允许格式、大小和数量限制。
- 桌面端支持拖拽和点击。
- 移动端显示“选择文件”“从相册选择”或“拍摄”的系统能力入口。
- 上传区使用浅色背景和虚线边界，但不占用过高空间。

### 13.2 上传中

- 显示文件名、大小、进度、速度或剩余状态。
- 提供取消操作。
- 多文件上传逐项显示，不用一个模糊的总进度替代全部状态。

### 13.3 成功与失败

- 成功显示文件图标、名称、大小、预览、替换和删除。
- 失败显示具体原因和重试按钮。
- 错误不能导致其他已上传文件丢失。
- 上传完成前，确认页明确显示未完成状态。

## 14. 选项卡片

视觉风格、角色类型和参考音色使用选项卡片，但外观需根据内容类型区分。

### 14.1 视觉风格卡片

- 以图片为主要识别内容。
- 卡片下方显示名称和最多两行描述。
- 选中时使用深绿边界和橙色六边形角标。
- 单选使用明确单选语义，不额外放一个空心圆制造重复信号。
- 图片比例统一，使用裁切，不拉伸。

### 14.2 角色类型

- 使用紧凑图标 + 名称按钮组。
- 当前类型使用深绿背景和白字。
- 不把每个角色类型设计成大尺寸宣传卡。

### 14.3 参考音色

- 明确命名为“参考音色”。
- 卡片包含播放按钮、名称、简短描述、标签和推荐标记。
- 支持多选，并允许一个首选项。
- 多选状态使用复选语义；首选项使用单独的“设为首选”操作。
- 支持不选择参考音色，只填写文字偏好。
- 显示提示：“参考音色仅用于表达偏好，最终效果以制作结果为准。”
- 音色列表、描述、试听地址和标签均来自 API。

## 15. 标签

- 标签用于有限的分类选项和状态，不用于所有按钮。
- 可选标签采用紧凑矩形圆角，不使用过度圆润的胶囊视觉。
- 选中标签使用浅绿背景、深绿文字和深绿边界。
- 警告标签可使用浅橙背景和深绿文字。
- 禁用标签保留原文可读性。
- 标签过多时自动换行，不横向挤压文字。
- 标签名称和排序来自 API。

## 16. 角色管理

- 已添加角色以紧凑列表或小型卡片展示姓名、类型、参考图和完成度。
- 新增角色由按钮触发抽屉或独立编辑区。
- 编辑角色复用同一表单，不为每个角色常驻显示完整字段。
- 删除需要确认，并说明相关参考图片也会从任务中移除。
- 支持拖拽排序时，同时提供键盘可操作的排序方式。
- 宽面板应采用“角色列表 + 当前角色编辑”的双栏结构，避免单列浪费空间。

## 17. 上下文侧栏、摘要与完整度

完整项目资料包摘要不作为所有步骤的常驻右侧栏。确认提交页面显示完整摘要；其他步骤可以显示与当前操作直接相关的“伴随式上下文”，以形成需求参考图中的产品化服务体验。

摘要可以包含：

- 封面缩略图。
- 项目名称与书名。
- 当前草稿状态。
- 各步骤完成度。
- 缺失项数量。
- 最近保存时间。

按步骤允许的伴随式上下文：

- 第一步：封面、项目名、客户名、资料完成清单。
- 第二步：角色参考图、已选视觉风格大图、已选标签摘要，以及这些选择如何交给制作团队。
- 第三步：当前参考音色、试听状态、参考素材清单和交接资料包说明。
- 第四步：完整项目资料包摘要、缺失项、授权确认和提交后流程。

规则：

- 只显示有助于当前填写的信息，不复制整个表单。
- 缺失项可以点击并定位到对应步骤。
- 不使用虚假的百分比；完成度必须有明确计算规则。
- 草稿状态和最近保存时间可以在顶部工具栏以一行紧凑状态显示，不需要独立摘要卡。
- 平板和移动端通过抽屉、折叠区或确认页集中展示。
- 侧栏内容必须随当前步骤变化，不能把同一张项目摘要卡机械复制到全部页面。
- 说明文案以事实描述服务流程，不使用夸张营销语言，不暗示系统具备 AI 生成能力。

## 19. 状态反馈

### 19.1 自动保存

- 操作栏持续显示“正在保存”“已保存”或“保存失败”。
- 成功状态保持低干扰，不频繁弹出 Toast。
- 失败状态保留到用户处理，并提供重试。

### 19.2 加载

- 首次页面加载使用结构化骨架屏。
- 按钮提交使用内联加载状态。
- 不使用全屏遮罩阻塞与当前请求无关的区域。

### 19.3 错误

- 字段错误显示在字段附近。
- 页面级错误放在相关内容顶部。
- 错误文案说明问题和解决方式，例如“手稿超过 200MB，请压缩后重新上传”。
- 未知错误显示请求编号，方便反馈给支持人员。

### 19.4 成功

- 提交成功页使用一次橙色六边形与深绿完成图标组合。
- 显示项目编号、项目名和提交时间。
- 主操作为“查看项目提交记录”，次操作为“返回我的书籍视频项目”。
- 不使用持续播放的庆祝动画。

## 20. 弹窗与抽屉

- 简短确认使用弹窗。
- 复杂编辑优先使用抽屉或独立页面。
- 移动端抽屉可升级为全屏页面。
- 删除确认明确显示删除对象名称和不可恢复性。
- 弹窗打开后锁定背景滚动并正确管理焦点。
- 关闭后焦点返回触发控件。

## 21. 动效

- 控件状态变化：120–160ms。
- 抽屉和步骤内容切换：180–220ms。
- 使用标准缓出曲线，不使用弹簧式夸张运动。
- 向导切换可以轻微横向位移 8–12px，表达前后顺序。
- 上传进度保持线性、连续。
- 支持 `prefers-reduced-motion`，关闭非必要位移和过渡。

## 22. i18n 设计规则

- 所有可见文案通过翻译键渲染。
- 中英文界面不同时并排展示双语标签。
- 动态枚举、标签、视觉风格和参考音色由 API 返回本地化内容。
- 按钮宽度为内容自适应并设置合理最小宽度，不按中文长度写死。
- 标题和表格列允许英文比中文长约 30% 至 60%。
- 文案溢出优先换行；编号、邮箱和文件名可以省略并提供完整提示。
- 日期、时间、数字和文件大小使用 locale 格式化。
- 界面语言与视频内容语言保持独立。
- 翻译缺失时记录错误并使用约定的回退语言，不能直接显示翻译键。

### 22.1 路由与语言切换

- 中文页面使用 `/zh-CN/...`，英文页面使用 `/en-US/...`。
- 路由中的 locale 与界面显示语言必须始终一致。
- 语言切换入口位于紧凑顶部工具栏的用户工具区域，不新增独立侧栏或大面积语言面板。
- 切换语言时保留当前页面、工单 ID、步骤、筛选和查询参数。
- 编辑工单期间切换语言不得丢失输入内容、上传队列或滚动上下文。
- 语言切换后控件可以因文案长度重新排版，但不能跳回列表首页。
- 面包屑、返回路径和步骤链接必须包含当前 locale。
- 不在同一页面同时显示中文和英文标题来代替路由级语言版本。
- 非法 locale 回退时只显示一次明确且低干扰的提示，不使用阻塞弹窗。

## 23. 无障碍规范

- 正文及关键控件满足 WCAG 2.1 AA 对比度目标。
- 所有交互控件可通过键盘访问。
- 焦点样式清晰且不被移除。
- 图标按钮具有可访问名称。
- 表单错误通过 `aria-describedby` 关联字段。
- 步骤条声明当前步骤。
- 上传进度通过可访问状态播报。
- 颜色不是唯一状态表达方式。
- 播放参考音色时提供暂停、当前状态和可访问名称。
- 移动端触控目标建议不小于 44px。

### 图标来源

### 视觉规则

- 默认功能图标采用线性或简洁面性风格，同一操作区域不混用明显不同的线宽和细节密度。
- 常用尺寸为 16px、18px、20px 和 24px。
- 紧凑按钮默认使用 16px 或 18px。

- 单色图标使用 `currentColor`，跟随当前文字或状态颜色。
- 普通图标使用 `text.secondary` 或 `brand.darkSerpent`。
- 主要操作图标跟随按钮文字颜色。
- 危险操作使用 `status.error`，不能使用品牌橙色表达删除。
- 禁用状态保持图形可识别，不只降低到极低透明度。
- 不使用图标渐变、投影、发光和无业务意义的动画。

### 交互规则

- 图标不能代替不明确的业务文字。创建、保存、提交和删除等关键操作默认使用“图标 + 文案”。
- 只有返回、关闭、更多、搜索等高度通用操作可以使用纯图标按钮。
- 纯图标按钮必须具有本地化的可访问名称和 Tooltip。
- Tooltip 文案使用 i18n 翻译键，不嵌入 SVG。
- 图标按钮的可点击区域桌面端不小于 32px，移动端不小于 44px。
- 相同动作在所有页面使用同一图标，例如“保存草稿”不能在不同步骤更换图形。
- 展开、折叠、播放和暂停必须显示当前状态，不能只依赖动态图形猜测。

### 资产处理

- 选中的图标复制进项目资产目录后使用，不从桌面路径直接加载。
- 文件统一采用英文 kebab-case 命名。
- 保留来源与授权记录。
- 清理 SVG 中的固定颜色、无效分组、脚本、外部链接和多余元数据。
- 保留正确 `viewBox`，不得通过拉伸改变比例。
- 不将含中文或英文文字的 SVG 用作界面文案，确保 i18n 可切换。
- 服务端如果返回图标配置，只返回受控 `iconKey`；前端映射到本地图标白名单。

## 24. Logo 策略

- 主应用页面、顶部工具栏和四步项目向导不要求显式展示 Logo。
- 不通过常驻 Logo 占用有限的工具栏和表单空间。
- 公司归属主要通过配色、字体和细节建立，不依赖重复品牌露出。
- 如果未来在登录落地页、关于页面或对外页面使用 Logo，则不得拉伸、改色、旋转、添加投影或自行反色。
- 当前提供的位图 Logo 作为品牌参考保留，不是本期 UI 开发的阻塞项。

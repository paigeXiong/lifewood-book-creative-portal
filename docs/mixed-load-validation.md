# 混合读写与数据完整性验证

`npm run bench:mixed` 在隔离服务中同时执行项目保存、图片上传、提交和列表读取，用于发现查询优化后的写入回退与一致性问题。本轮是短时本机验证，不是生产容量验收。

## 运行方式

需要 Node.js 22.13+ 与 .NET 10。已有开发服务运行时，使用独立构建目录：

```powershell
dotnet build services/platform-api/Lifewood.PlatformApi.csproj -c Release --artifacts-path C:/Aigc/artifacts/mixed-dotnet
npm run bench:mixed -- artifacts/mixed-dotnet/bin/Lifewood.PlatformApi/release/Lifewood.BookPortal.Server.dll
```

沿用 [读取基准](./performance-baseline.md) 的隔离规则：只监听 `127.0.0.1:5097`，端口占用时退出；每轮账号、数据库、附件、备份及协调锁均放在独立的 `artifacts/api-benchmark/<UUID>` 下。不能指定现有平台 URL 或业务数据目录。测试前后版本应顺序执行，避免同时构建或运行其他测试。

## 负载与断言

- 10,000 条后台合成记录，由停服后的 SQL 扩充生成；其中 20 条为草稿。背景记录含约 2 KB 简介和 16 个角色，超过当前表单的 600 字符简介、12 个角色限制，用于较重 JSON 读取压力，不代表一万份通过当前校验的真实提交。
- 两个客户各通过真实 API 新建两个有效项目，分别读取中英文选项，使用双语项目名与角色资料。保持默认草稿、文件和请求限制。
- 四条写入流程并发启动，每个项目连续保存 8 次、上传一张有效 PNG（1,049,476 字节，约 1 MiB）、校验并提交。每次保存检查版本递增，提交后检查最后一次保存的内容。
- 四个读工作线程分别读取两个客户的列表、客户统计和管理员列表，各 100 次，共 400 次；检查总数、分页条数、统计分类以及客户归属隔离。
- 重放同一上传 ID 和文件，检查附件 ID、版本和文件数量不变；重放同一提交键，检查只产生一次版本递增。
- 额外并发保存同一个项目版本，要求恰好一个成功、一个 409；重新加载后重试保存成功。旧版本新上传要求 409，另一客户读取或上传要求 404。
- 所有写入完成后校验数据库完整性、提交快照及幂等键；服务停止并重新启动后，逐项目比较完整响应和附件 SHA-256。磁盘必须恰好留下四个上传文件，避免重复或孤立文件。

报告先保存 `passed: false`，所有断言通过后才置为 `true`；失败保留报告并非零退出。预期 409 / 404 单独记录，不算异常。脚本不进行自动重试来隐藏错误。

## 延迟口径与限制

操作延迟从发送实际业务请求到收到完整响应体，不含预先获取 CSRF、准备数据、JSON 编码、响应 JSON 解码及断言。写入之间有 20 ms 间隔，读请求之间有 10 ms 间隔；读取路径预热，写入没有单独预热。

报告分别提供整个混合阶段、写流程仍活跃期间、与写请求重叠的样本。重叠由客户端 HTTP 请求开始和结束时间判断，不等于数据库锁等待；写请求不把自身算作重叠。写入结束后读取仍会继续，所以全部读取样本不能直接当作写入竞争下的延迟。

首次上传和提交各仅四个样本，P95 等于最大值。前后各运行一次，缓存与调度可影响结果，不能由此推断新增索引没有写入成本。本轮没有持续高并发、资源用量采样、真实网络中断或写入途中崩溃注入；重启校验发生在写入完成之后。

## 2026-09-14 对照结果

Windows 11、AMD Ryzen 5 4600H（12 逻辑核）、Node 24.16.0、.NET 10。对照版本分别为已有摘要/统计优化的版本，以及新增客户搜索和管理员列表索引后的版本。本轮只新增测试工具与文档，没有继续修改业务代码。

两轮五组完整性检查全部通过，均无非预期请求失败。以下为各操作全阶段 P95（毫秒）：

| 操作 | 每轮样本数 | 搜索索引前 | 搜索索引后 |
| --- | ---: | ---: | ---: |
| 草稿保存 | 32 | 19.83 | 23.17 |
| 首次上传 | 4 | 232.46 | 164.50 |
| 首次提交 | 4 | 99.94 | 109.74 |
| 客户列表 | 200 | 16.77 | 14.14 |
| 客户统计 | 100 | 20.02 | 15.96 |
| 管理员列表 | 100 | 419.97 | 31.71 |

与写请求重叠的读取子集：

| 操作 | 索引前样本数 | 索引前 P95（ms） | 索引后样本数 | 索引后 P95（ms） |
| --- | ---: | ---: | ---: | ---: |
| 客户列表 | 57 | 26.68 | 55 | 23.31 |
| 客户统计 | 26 | 27.31 | 26 | 25.75 |
| 管理员列表 | 1 | 703.73 | 15 | 58.28 |

管理员列表原版本执行较慢，只有一个请求与短时写入重叠；不能将该子集与新版本的十五个样本当作等量稳态对照。保存和提交尾部延迟略有上升，样本不足以判断稳定回退；本轮主要证明这些实际写入流程在两个版本上均保持正确。

另外用修改后的入口脚本回归原有 `bench:api` 模式，1,000 / 10,000 条背景、七个读取场景、并发 1 / 8，共 1,680 次计时请求全部通过。
